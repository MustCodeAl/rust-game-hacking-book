Lesson 5.2 / Listening edition

File Offsets, RVAs, and Live Addresses

Connect positions in a PE file to relative virtual addresses and the addresses Windows gives its loaded modules.

About 28 minutes

Section: Keep four address terms separate.

The P E, portable executable, map in Lesson 5.1 told us that an instruction can have one position in the EXE file and another in a running process. Suppose your debugger recorded an instruction at this value yesterday. To find it after restarting the game, you need to know which part of that number belonged to the module and which part Windows chose for that run.

We will use four names for the four different positions involved:

a preferred image base is where the file would like to be loaded;

a live module base is where Windows placed it in this process run;

an R V A, relative virtual address, is a distance from the beginning of the module;

a virtual address is the final live address used by the C P U, central processing unit.

An R V A is not a pointer stored in the game. It is arithmetic describing a location inside one loaded image. The P E file’s section table maps RVAs to sections such as code or data.

Do not confuse an R V A with a file offset. A file offset counts bytes in the EXE on disk. An R V A counts from the mapped image base after Windows has arranged sections according to virtual addresses and alignment. They can differ.

The complete vocabulary is worth making explicit:

These are coordinates in different spaces. Adding a live module base to a file offset is the binary-analysis version of adding meters to seconds: the numbers fit in an integer, but the operation has no useful meaning.

Section: Why an address moves.

Old notes often show an address such as this value. That may be the address from one run, not a permanent location.

Windows can load an executable at a different base address each run; that is what A S L R randomizes. The useful part that usually stays the same for an exact build is the distance from the module’s beginning: the Relative Virtual Address.

A S L R makes fixed absolute addresses less predictable. Windows can relocate an image when its P E metadata supports relocation. The module’s internal layout for that exact file usually stays the same, so base-plus-R V A reaches the same instruction even when the base changes.

Section: R V A is not a version check.

An R V A can move when the game is rebuilt. Keep all three checks:

exact supported game version;

live module base plus the version’s R V A;

exact original bytes or a unique pattern at the final address.

That is why the code-cave installers reject unknown bytes instead of hoping the address is close enough.
