Section: The host owns collection and validation.

The Windows layer should:

open the target with the least required rights;

verify game build and architecture;

resolve versioned roots and pointer paths;

copy fields with bounds and plausibility checks;

create ordinary owned records;

close or retain handles according to one clear owner.

Only step 5 crosses into Lua.

There are no process addresses in this type. A script cannot keep a stale pointer because it never receives one.

Why avoid raw pointers here? Lua can represent native objects through userdata. Full userdata has Lua-managed storage and a host-defined metatable; light userdata is essentially an unowned pointer value. If a native entity dies while a script retains its raw address, the same address may later belong to a different entity. A copied snapshot avoids that lifetime problem for observation. When a request needs persistent identity, use a validated handle rather than a remembered address.

A handle can pair a numbered slot with a generation counter. Every time a slot is reused for a new entity, its generation changes. Suppose Lua remembers slot 3, generation 6. Section: Put an abstraction barrier between bytes and game meaning.

An abstraction barrier is a rule about who may know a representation. The observer below the barrier knows that one build stores an entity position at a particular pointer path. Lua above the barrier knows only that an entity has an id, name, position, and alive state.

Alternative: The abstraction barrier is a translation desk: scripts ask about entities, while the observer translates those names into one build’s storage layout.

Section: Validate again at action time.

Between snapshot and request processing, an entity may disappear. Check:

the sequence is recent;

the entity still exists;

its current state permits the action;

all numbers are finite;

coordinates remain within known map bounds;

the per-script action budget is not exhausted.

This is a time-of-check/time-of-use issue. Validation during snapshot creation does not guarantee future state.

Narration: A unit can disappear after the snapshot was copied. Rechecking its identity when processing a request prevents acting on an outdated observation.

Section: Keep read and write capabilities separate.

Most analysis scripts need only snapshots and logs. Give them an observer A P I with no request function at all.

Section: Test the boundary without a game.

The lua-labs host uses a simulated snapshot. Add tests where Lua requests:

a missing entity ID;

0/0 or infinity as a coordinate;

an unknown action;

too many actions;

an action from an expired sequence.

The host should reject each request with a useful error and remain alive.

This architecture also makes the script portable. The same Lua logic can consume a recorded replay, a simulated world, or a live observer because it depends on the snapshot contract rather than Windows memory details.
