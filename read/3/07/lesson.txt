How Text Becomes Bytes in a Game

Section: Text is bytes plus an agreement.

The screen may show “Ford,” but memory stores bytes. An encoding explains how bytes represent characters.

Common forms include:

UTF-8—used by String and str;

UTF-16— many Windows “wide” APIs;

older single-byte encodings;

null-terminated C strings.

Keep four layers separate:

a character is the human idea, such as é;

a code point is the Unicode number assigned to that character idea;

a code unit is one storage unit used by an encoding, such as u8 for UTF-8 or u16 for UTF-16;

the bytes are the actual memory representation, with byte order relevant for multi-byte code units.

One visible character can use several code units. That is why byte count, UTF-16 unit count, Unicode scalar count, and what a reader sees on screen are not interchangeable lengths. Four short examples show every column coming apart:

Section: Compare A S C I I, Unicode, and Base64 with the same text.

A S C I I defines a 7-bit repertoire: 128 values, numbered 0 through 127, covering basic Latin letters, digits, punctuation, and control codes. An A S C I I value fits in an 8-bit byte with its top bit zero, as RFC 20 describes. Values above 127 belong to some other encoding, not standard A S C I I.

Unicode preserves those A S C I I assignments within a much larger repertoire. Its code points identify characters; UTF-8 and UTF-16 choose their stored code units and bytes. The Unicode UTF FAQ explains that relationship. Compare the same two-letter text, HI, in each representation. No terminator or byte-order mark is included:

Base64 encodes bytes as A S C I I text. It is reversible without a secret key, so encoding is not encryption. Standard Base64 uses the 64-symbol alphabet A–Z, a–z, 0–9, +, /; equals is padding. RFC 4648 defines these rules.

For 48 49, join the 16 bits and append two zero pad bits to complete a six-bit group: 010010 000100 100100. The group values are 18, 4, and 36, which select S, E, and k. Two input bytes leave one equals padding symbol, so the result is SEk=.

In brief: Choose the bytes before applying Base64. UTF-8 HI gives SEk=, while the UTF-16LE bytes 48 00 49 00 give SABJAA equals . The visible text alone does not determine a Base64 result.

The base64url variant in RFC 4648 replaces + with - and / with _. Some protocols allow omitted equals padding; follow the receiving protocol’s rule. The example needs neither replacement character, so its padded base64url form is also SEk=.

CString adds the terminator and rejects an interior \0, which would make a C function think the string ended early.

Keep the CString alive for as long as the foreign function may use pointer. Returning as_ptr() from a function after the CString is dropped creates a dangling pointer.

Also determine whether the foreign function copies the text during the call or stores the pointer for later. “The call returned” ends the borrow only in the first case. Ownership and lifetime are part of the string contract just as much as encoding and termination.

Alternative: Think of handing a friend the location of a note: if you shred the note before they read it, they find nothing. A dropped CString does the same.

Section: Observe a print function.

The debugger may reveal a call that receives a string pointer and screen or layout information. Calling it yourself requires knowing its:

calling convention;

parameter order and types;

ownership of the string;

required thread;

lifetime of any returned or stored pointer.

Do not guess a signature from one register. Collect several calls with different strings and compare them.

Section: Prefer an overlay for new UI.

Calling an undocumented internal print routine can be fragile. For new tool UI, a separate overlay or console is often easier to version, test, and remove.

Use an internal function only when the lesson is specifically about understanding that function and the target profile is exact.

Section: Keep the text contract together.

The bytes of a string need an encoding before they become text. UTF-16LE often has a zero high byte for an A S C I I-range letter; that byte alone does not end the string. A C-style terminator marks the end of the encoded sequence, and CString owns a terminated buffer while rejecting interior zeros. The pointer passed to a print function is useful only while that buffer remains alive, so tracing a text call means checking both its bytes and its lifetime. That is one part of a larger function contract: the caller and callee must also agree on argument positions, return values, and ownership.
