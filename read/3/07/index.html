Lesson 3.8 / Listening edition

How Text Becomes Bytes in a Game

Trace visible text to bytes, understand encodings and terminators, and build checked strings at FFI boundaries.

About 16 minutes

Section: Text is bytes plus an agreement.

The screen may show “Ford,” but memory stores bytes. An encoding explains how bytes represent characters.

Common forms include:

UTF-8—used by String and str;

UTF-16— many Windows “wide” APIs;

older single-byte encodings;

null-terminated C strings.

Keep four layers separate:

a character is the human idea, such as é;

a code point is the Unicode number assigned to that character idea;

a code unit is one storage unit used by an encoding, such as u8 for UTF-8 or u16 for UTF-16;

the bytes are the actual memory representation, with byte order relevant for multi-byte code units.

One visible character can use several code units. That is why byte count, UTF-16 unit count, Unicode scalar count, and what a reader sees on screen are not interchangeable lengths. Four short examples show every column coming apart:

The practical consequence: a buffer sized from “the name is at most 16 characters” can be far too small, and code that truncates a string at a fixed byte count can cut a character in half and produce bytes that no longer decode. Always say which of these four lengths a number refers to.

Section: Locate a known string.

In the offline Wesnoth target, open a terrain description and search memory for one distinctive phrase using the appropriate text encoding.

Change the selected tile and repeat. A static label may stay at one address, while a formatted output buffer changes.

Set a read breakpoint on the first byte of a promising string, trigger the description, and inspect the code that consumes its address.

Follow the pointer in the dump and identify:

where the string begins;

where it ends;

whether a zero terminator follows it;

which encoding makes the bytes readable;

whether the memory is static or temporary.

Section: Endianness is not encoding.

Endianness controls byte order inside multi-byte numbers. Encoding controls how bytes represent text. They are different ideas.

Section: Use CString for C boundaries.

Many C-style functions expect a zero byte at the end:

CString adds the terminator and rejects an interior \0, which would make a C function think the string ended early.

Keep the CString alive for as long as the foreign function may use pointer. Returning as_ptr() from a function after the CString is dropped creates a dangling pointer.

Also determine whether the foreign function copies the text during the call or stores the pointer for later. “The call returned” ends the borrow only in the first case. Ownership and lifetime are part of the string contract just as much as encoding and termination.

Section: Observe a print function.

The debugger may reveal a call that receives a string pointer and screen or layout information. Calling it yourself requires knowing its:

calling convention;

parameter order and types;

ownership of the string;

required thread;

lifetime of any returned or stored pointer.

Do not guess a signature from one register. Collect several calls with different strings and compare them.

Section: Trace a real text call before changing it.

On the Den of Onis map in offline Wesnoth 1.14.9, right-click a Ford tile and open Terrain Description. Search for a distinctive part of its text, then set a read breakpoint on a confirmed byte and open the description again. In the book’s run, the live string began at this value. Stepping out reached the print path at this value: e d x led to the text object and the call at this value printed it.

At this point, answer the text questions: which bytes were read, where does the string end, who owns its buffer, and does the print call keep the pointer? The breakpoint and the changing description provide the evidence. They do not require an injected D L L, dynamic link library.

Section: Prefer an overlay for new UI.

Calling an undocumented internal print routine can be fragile. For new tool UI, a separate overlay or console is often easier to version, test, and remove.

Use an internal function only when the lesson is specifically about understanding that function and the target profile is exact.

Section: Keep the text contract together.

The bytes of a string need an encoding before they become text. UTF-16LE often has a zero high byte for an A S C I I-range letter; that byte alone does not end the string. A C-style terminator marks the end of the encoded sequence, and CString owns a terminated buffer while rejecting interior zeros. The pointer passed to a print function is useful only while that buffer remains alive, so tracing a text call means checking both its bytes and its lifetime. That is one part of a larger function contract: the caller and callee must also agree on argument positions, return values, and ownership. What a D L L Function Promises Its Caller reconstructs those promises later, before the in-process D L L labs.
