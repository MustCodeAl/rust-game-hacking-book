Section: Break on writes.

Set a hardware breakpoint on write, covering four bytes at the gold address. The lesson uses x64dbg, but any debugger that can watch an address will do:

x64dbg

Select the four bytes in the dump, right-click, and choose Breakpoint, then Hardware, Write, then Dword.

WinDbg

Type ba w4 followed by the address, for example ba w4 0A3C1230, to break on a four-byte write. Then type g to let the game run.

Cheat Engine

Right-click the gold entry in the address list and choose Find out what writes to this address. Cheat Engine lists each instruction that writes it, with a count.

A hardware memory breakpoint does not replace the game’s instruction bytes. The debugger programs special CPU debug registers with an address, access type, and width. When an instruction writes across that watched range, the CPU raises a debug exception and Windows reports it to the debugger.

The width matters. Gold is believed to be a four-byte value, so watch all four bytes. Watching one byte can still trigger, but it hides whether the game wrote the complete integer or only part of it.

This breakpoint watches a data address, not one fixed instruction. If three different functions write gold, the same watch can reveal all three. A software breakpoint placed on a code address answers the opposite question: “When does this exact instruction execute?”

Section: Ask the five assembly questions.

Apply the five questions to the paused instruction:

What is read? The current gold and the price in a register.

What is written? Four bytes at the gold field.

How many bytes? dword ptr means 32 bits.

Signed or unsigned? Test nearby comparisons before deciding.

Where next? The following instruction unless a branch changes the path.

Now compare the price register with the unit’s price. In the example run, it should be 15 and the destination should be the gold address that changed from 100 to 85. Matching both is stronger evidence than recognizing sub alone.

That last line matters. Later branches may inspect zero, sign, carry, or overflow flags. Replacing the subtraction changes both the stored gold and those flags. Before a temporary patch, step forward and check whether nearby conditional jumps consume them.

The effective address calculation does not dereference reg and then add an offset to the loaded value. It adds the offset to the register first, then reads memory at the resulting address. Keep “calculate an address” separate from “read the value at that address.”

For an instruction such as:

read it from the inside outward:

take the address currently stored in esi;

add hexadecimal offset hexadecimal 3 0;

treat the four bytes at that final address as the destination;

subtract the lower 32 bits of eax from that destination;

store the result back to the same four bytes;

update CPU flags for later branches.

The bracketed expression accesses memory. Without brackets, esi+30h would be an address calculation rather than a read or write of the bytes at that address.

Read the live value of esi in the register panel and add hexadecimal 3 0 yourself. For example, if esi holds hexadecimal 0 A 3 C 1 2 0 0, the destination is hexadecimal 0 A 3 C 1 2 0 0 + hexadecimal 3 0 equals hexadecimal 0 A 3 C 1 2 3 0. If the sum equals the candidate gold address, this instruction writes the gold you found.

Section: Test with a reversible patch.

Copy the original instruction bytes first, so you can write them back. Then temporarily replace the entire subtraction instruction with the same number of nop bytes (Example: The length comes from the encoding. sub [edx+4], eax is the three bytes 29 42 04, so it takes three 90 bytes. sub [edx+hexadecimal 1 2 3 4], eax is the six bytes 29 82 34 12 00 00, so it takes six. The disassembly's bytes column shows the count.).

Section: Turn one discovery into a repeatable patch.

Our tools will not hardcode “whatever address worked once.” They will:

open the controlled process;

locate a module or scan a known pattern;

confirm the expected original bytes;

apply a temporary patch;

restore the bytes on exit.

Checking the original bytes is crucial. Refusing to patch an unknown version is safer than writing to the wrong place.
