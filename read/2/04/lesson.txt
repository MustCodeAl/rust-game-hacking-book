From a Game Value to the Code That Changes It

Section: Attach x64dbg.

Launch Wesnoth, begin a local match, and find the gold address again. Then attach x64dbg to the running process.

The C P U, central processing unit, view contains four useful areas:

disassembly—the instructions near the current position;

registers—the C P U’s current scratch values;

dump—raw memory;

stack—return addresses and temporary data.

Attaching may pause in Windows system code. That is normal. Resume the process before triggering your experiment.

Section: Break on writes.

Set a hardware breakpoint on write, covering four bytes at the gold address. The lesson uses x64dbg, but any debugger that can watch an address will do:

x64dbg

Select the four bytes in the dump, right-click, and choose Breakpoint, then Hardware, Write, then Dword.

WinDbg

Type ba w4 followed by the address, for example ba w4 0A3C1230, to break on a four-byte write. Then type g to let the game run.

Cheat Engine

Right-click the gold entry in the address list and choose Find out what writes to this address. Cheat Engine lists each instruction that writes it, with a count.

A hardware memory breakpoint does not replace the game’s instruction bytes. The debugger programs special C P U debug registers with an address, access type, and width. When an instruction writes across that watched range, the C P U raises a debug exception and Windows reports it to the debugger.

The width matters. Gold is believed to be a four-byte value, so watch all four bytes. Watching one byte can still trigger, but it hides whether the game wrote the complete integer or only part of it.

This breakpoint watches a data address, not one fixed instruction. If three different functions write gold, the same watch can reveal all three. A software breakpoint placed on a code address answers the opposite question: “When does this exact instruction execute?”

In brief: Watching a data address finds every writer of a value. A code breakpoint tells you when one particular instruction runs.

Section: Ask the five assembly questions.

Apply the five questions to the paused instruction:

What is read? The current gold and the price in a register.

What is written? Four bytes at the gold field.

How many bytes? dword ptr means 32 bits.

Signed or unsigned? Test nearby comparisons before deciding.

Where next? The following instruction unless a branch changes the path.

Now compare the price register with the unit’s price. In the example run, it should be 15 and the destination should be the gold address that changed from 100 to 85. Matching both is stronger evidence than recognizing sub alone.

The effective address calculation does not dereference reg and then add an offset to the loaded value. It adds the offset to the register first, then reads memory at the resulting address. Keep “calculate an address” separate from “read the value at that address.”

Section: Register names can select overlapping bits.

e a x, a x, a h, and a l are views of the same register family, not four independent containers. e a x selects 32 bits, a x its low 16, a h bits 15–8, and a l bits 7–0. In the course’s 32-bit target, e a x is the full-width view. The diagram also shows the wider r a x available in 64-bit mode.

In 64-bit mode, a write to e a x also clears r a x bits 63–32. Writes to a x, a h, or a l preserve bits outside the selected part. Microsoft’s x64 register reference documents this distinction. For the gold instruction, the operand width still tells us that exactly four memory bytes are changed.

In brief: A register name is a width clue. Treat an 8-bit, 16-bit, and 32-bit write as different state changes even when they belong to one register family.

The bracketed expression accesses memory. Without brackets, e s i+30h would be an address calculation rather than a read or write of the bytes at that address.

Section: Test with a reversible patch.

Copy the original instruction bytes first, so you can write them back. Then temporarily replace the entire subtraction instruction with the same number of nop bytes.

Resume and recruit another unit. If gold no longer decreases, this instruction is the one that subtracts the price. Restore the original bytes immediately afterward.

Narration: A patch even one byte short leaves bytes the C P U decodes as some other instruction, which can crash the game. That is why you copy the originals first.

Section: Turn one discovery into a repeatable patch.

Our tools will not hardcode “whatever address worked once.” They will:

open the controlled process;

locate a module or scan a known pattern;

confirm the expected original bytes;

apply a temporary patch;

restore the bytes on exit.

Checking the original bytes is crucial. Refusing to patch an unknown version is safer than writing to the wrong place.

Section: Clean up.

Remove the breakpoint through x64dbg’s Breakpoints tab and confirm the original instruction is restored.

The scan gave us a candidate value; the write breakpoint gave us a specific instruction and the register values from one recruitment.
