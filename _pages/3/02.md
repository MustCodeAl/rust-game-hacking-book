## External means “a separate process”

Our tool runs beside the game, not inside it. Windows must grant a process handle with specific rights before the tool can read or write memory.

For this lab, pass the process ID and verified gold address on the command line. Automatic process discovery comes later.

## Own the handle with a type

A Windows handle is a resource that must be closed. Rust’s `Drop` trait gives it an automatic cleanup path:

```rust
use windows::Win32::{
    Foundation::{CloseHandle, HANDLE},
    System::Threading::{
        OpenProcess, PROCESS_QUERY_INFORMATION, PROCESS_VM_OPERATION,
        PROCESS_VM_READ, PROCESS_VM_WRITE,
    },
};

struct Process {
    handle: HANDLE,
}

impl Process {
    fn open(process_id: u32, allow_write: bool) -> windows::core::Result<Self> {
        let mut access = PROCESS_QUERY_INFORMATION | PROCESS_VM_READ;
        if allow_write {
            access |= PROCESS_VM_OPERATION | PROCESS_VM_WRITE;
        }

        // SAFETY: `process_id` is a value, inheritance is disabled, and the
        // returned handle is owned by `Process` and closed in `Drop`.
        let handle = unsafe { OpenProcess(access, false, process_id)? };
        Ok(Self { handle })
    }
}

impl Drop for Process {
    fn drop(&mut self) {
        // SAFETY: this instance owns the live handle and closes it exactly once.
        let _ = unsafe { CloseHandle(self.handle) };
    }
}
```

The rest of the program cannot forget to close the handle.

## Read into a byte buffer

Put `ReadProcessMemory` behind a method:

```rust
use std::ffi::c_void;
use windows::Win32::System::Diagnostics::Debug::ReadProcessMemory;

impl Process {
    fn read_exact(&self, address: usize, buffer: &mut [u8]) -> windows::core::Result<()> {
        let mut bytes_read = 0_usize;

        // SAFETY:
        // - `buffer` is valid for exactly `buffer.len()` writable bytes.
        // - Windows validates the remote address against the target process.
        // - `self.handle` remains open for this call.
        unsafe {
            ReadProcessMemory(
                self.handle,
                address as *const c_void,
                buffer.as_mut_ptr().cast(),
                buffer.len(),
                Some(&mut bytes_read),
            )?;
        }

        if bytes_read != buffer.len() {
            return Err(windows::core::Error::from_win32());
        }
        Ok(())
    }

    fn read_u32(&self, address: usize) -> windows::core::Result<u32> {
        let mut bytes = [0_u8; 4];
        self.read_exact(address, &mut bytes)?;
        Ok(u32::from_le_bytes(bytes))
    }
}
```

The public method returns a normal `u32`. Raw pointers never escape the wrapper.

## Read the verified gold

```rust
use anyhow::{Context, Result};

fn main() -> Result<()> {
    let process_id: u32 = std::env::args()
        .nth(1)
        .context("usage: memory_lab <pid> <hex-address>")?
        .parse()
        .context("PID must be a decimal number")?;

    let address_text = std::env::args()
        .nth(2)
        .context("missing address")?
        .trim_start_matches("0x")
        .replace('_', "");

    let address = usize::from_str_radix(&address_text, 16)
        .context("address must be hexadecimal")?;

    let process = Process::open(process_id, false)?;
    let gold = process.read_u32(address)?;
    println!("Gold at {address:#x}: {gold}");
    Ok(())
}
```

Run the tool from an ordinary terminal in the VM. If Windows denies access, report the error; do not automatically demand more privileges.

## Add a guarded write

Writing should be opt-in and should verify the expected old value first:

```rust
use windows::Win32::System::Diagnostics::Debug::WriteProcessMemory;

impl Process {
    fn write_u32_if(
        &self,
        address: usize,
        expected: u32,
        replacement: u32,
    ) -> windows::core::Result<bool> {
        if self.read_u32(address)? != expected {
            return Ok(false);
        }

        let bytes = replacement.to_le_bytes();
        let mut written = 0_usize;

        // SAFETY: `bytes` is a live readable buffer; Windows validates the
        // destination; the handle was opened with write and operation rights.
        unsafe {
            WriteProcessMemory(
                self.handle,
                address as *const c_void,
                bytes.as_ptr().cast(),
                bytes.len(),
                Some(&mut written),
            )?;
        }

        Ok(written == bytes.len())
    }
}
```

Open the handle with `allow_write: true` only when the user explicitly requests a lab change.

## Defeat the moving-address problem

Replace the raw address with the pointer path verified in lesson 2.9:

```rust
fn resolve_chain(
    process: &Process,
    start: usize,
    offsets: &[usize],
) -> windows::core::Result<usize> {
    let mut address = start;

    for &offset in offsets {
        let pointer = process.read_usize(address)?;
        address = pointer.checked_add(offset)
            .ok_or_else(windows::core::Error::from_win32)?;
    }

    Ok(address)
}
```

Add `read_usize` exactly like `read_u32`, using `size_of::<usize>()` bytes and `usize::from_le_bytes`.

## Make failure useful

Test these cases:

- wrong PID;
- target closed;
- malformed hex address;
- unreadable address;
- expected value does not match;
- pointer in the chain is zero.

A good low-level tool is not the one that never sees errors. It is the one that sees errors clearly and stops before making a bad write.
