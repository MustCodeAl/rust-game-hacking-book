This lab uses x64dbg only. We are learning the shape of a detour before asking Rust to manage one.

## Choose a harmless trigger

Use the terrain-description menu path identified in the previous lesson. It gives us an easy trigger without changing competitive or networked behavior.

![The terrain-description function](/assets/images/2/7/wesnoth2.png)

Pause the game and choose a hook site with enough complete instructions for a jump. Record:

```text
Hook address:
Original instructions:
Original bytes:
Total byte length:
Return address:
```

Do not continue until the return address points to the first untouched instruction.

## Find a suitable cave

For this historical debugger exercise, locate executable padding inside the controlled module.

![An empty-looking area near the end of the module](/assets/images/2/7/wesnoth1.png)

“Looks empty” is not enough for production tooling. A robust tool allocates its own memory and assigns the correct protection. Here, the debugger-only lab is about the control flow.

## Build the smallest detour

Start with no extra behavior:

```nasm
; cave
; replay the complete instructions removed from the hook
jmp return_address
```

At the hook site, write a jump to the cave and fill any remaining whole bytes with `nop`.

![A jump from the hook into the cave](/assets/images/2/7/wesnoth4.png)

Set breakpoints at:

- the hook;
- the first cave instruction;
- the return address.

Trigger the menu once. You should see the breakpoints in that order. This proves the path before new logic complicates it.

![The cave breakpoint firing](/assets/images/2/7/wesnoth6.png)

## Add one observable change

Only after the round trip works, add a tiny change such as writing a known value to the already-identified gold field.

![A cave containing the test change](/assets/images/2/7/wesnoth7.png)

Trigger once, observe once, and stop. If the wrong action triggers it, your hook is too broad or your model is wrong.

## Diagnose by symptom

| Symptom | Likely place to check |
|---|---|
| Crash before cave | Hook bytes or jump destination |
| Cave never runs | Wrong trigger or hook not reached |
| Crash after cave | Saved instruction or return address |
| Game acts oddly later | Register, flag, or stack state was changed |
| Runs more than once | Trigger path or re-entry assumption |

Change one variable per retry.

## Restore the target

Before closing the debugger:

1. pause the game;
2. restore the hook’s original bytes;
3. remove breakpoints;
4. verify the original behavior;
5. restore the VM snapshot if anything is uncertain.

The lasting result is your map of the detour, not the temporary patch.
