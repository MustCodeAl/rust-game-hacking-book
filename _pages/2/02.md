You do not need to memorize the whole x86 instruction set. Start with a handful of verbs.

## Moving data

`mov destination, source` copies data:

```nasm
mov eax, 25        ; eax now contains 25
mov ebx, eax       ; ebx now contains 25
```

Square brackets mean “use the memory at this address”:

```nasm
mov eax, [rcx]     ; read 4 bytes from the address in rcx
mov [rcx], eax     ; write 4 bytes to that address
```

Without brackets, `rcx` is a number. With brackets, that number is treated as an address.

## Doing math

```nasm
add eax, 10        ; eax = eax + 10
sub eax, 3         ; eax = eax - 3
inc eax            ; eax = eax + 1
dec eax            ; eax = eax - 1
```

The equivalent Rust is easier to read:

```rust
let mut value = 25_i32;
value += 10;
value -= 3;
value += 1;
value -= 1;
```

## Comparing and branching

`cmp` performs a comparison and updates flags. A jump reads those flags:

```nasm
cmp eax, 0
je player_is_dead
```

`je` means “jump if equal.” Common jumps include:

| Instruction | Meaning after `cmp left, right` |
|---|---|
| `je` / `jz` | equal / zero |
| `jne` / `jnz` | not equal / not zero |
| `jg` | greater, signed |
| `jl` | less, signed |
| `ja` | above, unsigned |
| `jb` | below, unsigned |
| `jmp` | always jump |

Signed and unsigned matter because the same bits can be read in different ways. `0xFFFF_FFFF` is `4,294,967,295` as a `u32`, but `-1` as an `i32`.

Rust makes that choice visible in the type:

```rust
let signed = -1_i32;
let unsigned = u32::MAX;

assert_eq!(signed.to_ne_bytes(), unsigned.to_ne_bytes());
```

## Calls, returns, and the stack

`call` jumps into a function and remembers where to return. `ret` goes back.

```nasm
call calculate_damage
; execution continues here after `ret`
```

The stack is a last-in, first-out area used for return addresses, saved registers, and some local values:

```nasm
push rbx
; use rbx
pop rbx
ret
```

Imagine stacking trays. The last tray placed on top is the first one removed.

## Address calculations

This pattern appears constantly:

```nasm
mov eax, [rcx+30]
```

Read it as: “Start at the address in `rcx`, move forward `0x30` bytes, then read a 32-bit value.” If `rcx` points to a player object, offset `0x30` might be a field such as health.

A Rust struct expresses the idea by name:

```rust
#[repr(C)]
struct PlayerSnapshot {
    id: u32,
    team: u32,
    health: u32,
}
```

`#[repr(C)]` asks Rust for a predictable C-compatible field layout. We only rely on a layout after confirming its offsets; guessing a struct from one screenshot is not enough.

## `lea` does math, not a read

`lea rax, [rcx+rdx*4]` calculates an address-like number and stores it in `rax`. Despite the brackets, it does not read the pointed-to memory.

```nasm
lea rax, [rcx+rdx*4]  ; rax = rcx + rdx*4
```

Compilers also use `lea` for ordinary arithmetic, so do not assume every result is a pointer.

## A five-question reading method

For each instruction, ask:

1. What is read?
2. What is written?
3. How many bytes are involved?
4. Is a number signed or unsigned?
5. Where can execution go next?

Answer those five questions one instruction at a time. A long function becomes a trail of small facts.
