## Three layers

Keep the client split into:

```text
TCP transport
↕
frame reader/writer
↕
typed protocol messages
```

The parser should work on byte slices without a network. The transport should move bytes without understanding chat or game rules.

## Connect with timeouts

```rust
use std::{
    net::{SocketAddr, TcpStream},
    time::Duration,
};

fn connect_local(address: SocketAddr) -> std::io::Result<TcpStream> {
    if !address.ip().is_loopback() {
        return Err(std::io::Error::new(
            std::io::ErrorKind::PermissionDenied,
            "this course client only connects to loopback",
        ));
    }

    let stream = TcpStream::connect_timeout(&address, Duration::from_secs(3))?;
    stream.set_read_timeout(Some(Duration::from_secs(5)))?;
    stream.set_write_timeout(Some(Duration::from_secs(5)))?;
    Ok(stream)
}
```

The loopback check encodes the scope of the exercise directly in the program.

## Write the complete frame

`write` may send only part of a buffer. `write_all` keeps going:

```rust
use std::io::{self, Write};

fn write_frame(stream: &mut impl Write, payload: &[u8]) -> io::Result<()> {
    let length = u32::try_from(payload.len())
        .map_err(|_| io::Error::new(io::ErrorKind::InvalidInput, "frame too large"))?;

    stream.write_all(&length.to_be_bytes())?;
    stream.write_all(payload)?;
    stream.flush()
}
```

Use the exact framing found in your local protocol; this is a generic example.

## Turn messages into bytes

```rust
fn send_message(stream: &mut TcpStream, message: &Message) -> anyhow::Result<()> {
    let payload = encode_message(message)
        .map_err(anyhow::Error::msg)?;
    write_frame(stream, &payload)?;
    Ok(())
}
```

Compression and checksums belong between message encoding and frame writing if the protocol uses them.

## Receive without assuming timing

```rust
fn receive_message(stream: &mut TcpStream) -> anyhow::Result<Message> {
    let payload = read_frame(stream, 1_048_576)?;
    Ok(parse_message(&payload)?)
}
```

A timeout is not necessarily a broken connection. Decide whether the protocol expects a response, a periodic ping, or silence.

## Model the session

```rust
enum ClientState {
    Disconnected,
    Connected,
    Introduced { nickname: String },
    InLobby,
    Closed,
}
```

Only send messages valid for the current state. If the server’s response does not match the expected transition, log it and stop instead of continuing with a confused session.

## A small main loop

```rust
fn run(address: SocketAddr, nickname: String) -> anyhow::Result<()> {
    let mut stream = connect_local(address)?;

    send_message(&mut stream, &Message::Chat {
        sender: nickname,
        text: "hello from the Rust lab".into(),
    })?;

    let response = receive_message(&mut stream)?;
    println!("local server replied: {response:?}");
    Ok(())
}
```

Real protocols usually require a handshake before chat. Implement the observed state sequence rather than jumping directly to a message that happened later.

## Be a polite client

Add:

- message and connection rate limits;
- maximum frame sizes;
- read and write timeouts;
- useful disconnect reasons;
- clean socket shutdown;
- no automatic reconnect storm.

The goal is a clear protocol implementation for a server you control, not a script that hammers an endpoint until something responds.
