🔍 Lesson 2.8Instructions, Debuggers, and Addresses

How Pointer Paths Survive Restarts

Trace the player object back to a verified starting point and prove the pointer path across restarts.

About 20 minutes

Start from behavior

Section titled “Start from behavior”

Use offline, 32-bit Wesnoth 1.14.9. Find the current player’s gold again and set a write breakpoint on its four bytes. Instead of recruiting, end a turn so income changes that value.

These addresses are exact only for Wesnoth 1.14.9 32-bit. If your instruction differs, use your build’s values instead of forcing these numbers onto it.

A pointer path is a route through an object graph

Section titled “A pointer path is a route through an object graph”

Each dereference moves from one object to another. The observed root 0x017EED18 is an absolute address for the pinned course build, not an RVA. Confirm that it still points into the expected module in your run. A portable profile would store the root’s RVA and first discover the module’s current base, as Lesson 2.7 explained. The heap objects reached afterward may move between runs, which is why the path reads their current addresses rather than saving yesterday’s final address.

A path is stable only under stated conditions. It may depend on:

  • the exact executable build;
  • a local match being active;
  • the current player or side object existing;
  • the same layout and pointer width;
  • each intermediate page being readable at the moment of use.

Validate every edge, not only the final gold. A non-null pointer can still be stale or point to the wrong object. Check module ranges, page protections, alignment, and a few field invariants before trusting the final value.

Build the chain manually

Section titled “Build the chain manually”

In Cheat Engine, add a pointer entry by hand using the module and the offsets you observed.

Be careful about order. A displayed list of offsets may be applied from the module outward or shown in reverse depending on the tool. For this exact build, enter base address 0x017EED18, first offset 0xA90, and final offset 0x4. The resolved value should equal the gold shown in the game.

Restart tests

Section titled “Restart tests”

One successful run proves very little. Test:

  1. close Wesnoth completely;
  2. start it again;
  3. begin a new local match;
  4. confirm the pointer entry resolves;
  5. repeat at least three times.

Also test a state where no match is active. A good tool should report “player object unavailable,” not crash or read address zero.

What counts as “stable”

Section titled “What counts as “stable””

The path is stable only for the target version and states you tested. The absolute root in this example also depends on the module loading where it did in the verified course run; a relocated module requires base-plus-RVA resolution. Game updates can change layouts and offsets. Document:

  • game version and architecture;
  • module name;
  • offsets in traversal order;
  • the expected final type;
  • how many restarts passed;
  • known states where the chain is unavailable.
