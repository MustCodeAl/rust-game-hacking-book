The [Rust Primer](/pages/1/05/) introduced `Some`, `None`, `Ok`, and `Err`.
Here we follow those shapes through several operations. An inventory slot
may be missing, a purchase may fail, and a dash may be cooling down. Each
case deserves a value that tells the caller what happened.

The examples use ordinary arrays and numbers in an invented game. The
traces simulate those examples in the page; changing a control never reads
or writes another program's memory. Every trace starts with a worked run.
Typing and recall practice are optional.

## Transform a present value with `map`

An `Option<u32>` contains a number or contains no number. `map` applies a
function to the number inside `Some`, then puts the answer back in `Some`.
For `None`, it returns `None` without calling the function.

```rust
let price = Some(8_u32);
let doubled = price.map(|n| n * 2); // Some(16)
```

`|n| n * 2` is a **closure**: a small function written where it is needed.
The bars name its input; the expression computes its output. A closure may
also borrow values from the surrounding scope, such as `budget` below.
Closures are functions with capture; they do not run merely because you
write them down.

## Chain another optional operation with `and_then`

The next calculation can itself have no answer: an unsigned subtraction
cannot represent a negative amount. `and_then` calls a function returning
another `Option`, and keeps a single layer of `Some` or `None`.

<SpeedType id="rust-option-chain" title="Follow an optional price" recall={[{text:"costs.get(slot).copied()",hint:"Check the slot, then copy a present numeric price out of the borrowed result."},{text:"map(|n| n * 2)",hint:"Transform a present price into double that price."},{text:"and_then(|n| budget.checked_sub(n))",hint:"Chain a calculation that can itself have no answer."}]}>

```rust
fn quoted_balance(slot: usize, budget: u32) -> Result<u32, &'static str> {
    let costs = [4_u32, 8, 12];
    let price = costs.get(slot).copied();
    let doubled = price.map(|n| n * 2);
    let left = doubled.and_then(|n| budget.checked_sub(n));
    left.ok_or("not affordable")
}
```

</SpeedType>

With slot 1 and budget 20, the sequence is `Some(8)` → `Some(16)` →
`Some(4)` → `Ok(4)`. With slot 4, `get` returns `None`; both closures are
skipped. `ok_or` turns a missing answer into an error with a reason. This
example deliberately gives the same reason for a missing item and a high
price. Use distinct error variants when callers need to distinguish them.

<MarginNote kind="code">A closure returning a plain number fits map. A closure returning Option fits and_then. Using map for the latter would produce a nested Option.</MarginNote>

## Carry a failure reason through `Result`

`Result::map` changes an `Ok` value and leaves `Err` alone. `map_err` changes
an error and leaves `Ok` alone. `and_then` chains another operation that can
return an error. The success path keeps flowing; the first error passes
through without running later success closures.

```rust
fn doubled_score(reading: Result<u8, &'static str>) -> Result<u8, &'static str> {
    reading
        .map(|n| u16::from(n) * 2)
        .and_then(|n| u8::try_from(n).map_err(|_| "score too large"))
}
```

Widening to `u16` before multiplication gives room for double any `u8`.
`try_from` checks whether that answer fits back into `u8`. Converting an
error with `map_err` is an explicit choice: here the exact numeric
conversion error is replaced with a short domain description.

## Let `?` return the first error

`?` takes the value out of `Ok` so the next line can use it. On `Err`, it
returns from the enclosing function immediately, converting the error to
the function's error type through `From` when necessary. It does not
retry, recover, or turn an error into a default value.

<SpeedType id="rust-fallible-purchase" title="Stop a purchase on its first failure" recall={[{text:"map_err(|_| \"bad cost\")?",hint:"Give a parsing failure a domain reason, then return early on that failure."},{text:"checked_sub(cost).ok_or(\"not enough gold\")?",hint:"Reject an unsigned underflow, attach its reason, and continue only on success."}]}>

```rust
fn buy(text: &str, gold: u32) -> Result<u32, &'static str> {
    let cost = text.parse::<u32>().map_err(|_| "bad cost")?;
    let left = gold.checked_sub(cost).ok_or("not enough gold")?;
    Ok(left)
}
```

</SpeedType>

The default trace buys a 4-gold item with 12 gold. Invalid text stops before
subtraction; an excessive cost stops before `Ok(left)`. Returning zero gold
after an exact-price purchase is still success.

## Give each state only the data it needs

Separate `ready: bool` and `ticks: u32` fields permit contradictory
combinations such as “ready with five cooldown ticks.” An **enum with
data** puts the alternatives into one value:

```rust
enum Dash {
    Ready,
    Cooling { ticks: u32 },
}

fn tick(state: Dash) -> Dash {
    match state {
        Dash::Cooling { ticks } if ticks > 1 => Dash::Cooling { ticks: ticks - 1 },
        Dash::Cooling { .. } => Dash::Ready,
        Dash::Ready => Dash::Ready,
    }
}
```

`Cooling` carries a count. `Ready` carries none. `tick` takes ownership of
the old state and returns the next one. The guard `if ticks > 1` adds a
condition to the first matching pattern; the following arm handles the
remaining cooldown counts. `..` means those fields are not needed here.

## Use patterns for shape and guards for conditions

`let else` names values from the expected shape and exits otherwise.
Its `else` branch must diverge: for example, return from the function.
`matches!` asks whether a value matches a pattern and produces a `bool`.
A **match guard** checks an additional condition after a pattern matches.

```rust
fn next_action(player_health: Option<u32>) -> &'static str {
    let Some(health) = player_health else { return "no player"; };
    let alive = matches!(health, 1..=100);
    match health {
        n if n < 25 && alive => "heal",
        0 => "respawn",
        _ => "wait",
    }
}
```

`1..=100` includes both endpoints. A player at zero health does not take
the healing arm, because `alive` is false. The final `_` catches other
numeric values. For an enum representing distinct application states,
prefer named arms so adding a new variant requires a deliberate decision.

<MarginNote kind="brief">A pattern identifies the value's shape. A guard tests a condition. The selected arm produces an answer; only one arm runs.</MarginNote>

## Cheatsheet: outcomes and states

| Need | Expression | What it does |
| --- | --- | --- |
| Change an optional success | `option.map(f)` | Runs `f` only for `Some`. |
| Chain optional work | `option.and_then(f)` | `f` returns `Option`; no extra nesting. |
| Supply a missing-value reason | `option.ok_or(error)` | Produces `Result`. |
| Change a failure reason | `result.map_err(f)` | Runs `f` only for `Err`. |
| Chain fallible work | `result.and_then(f)` | `f` returns `Result`. |
| Leave on failure | `result?` | Continues with success or returns the error. |
| Store distinct states | `enum` with data | Each variant carries its own fields. |
| Bind or exit | `let Pattern = value else { return ...; };` | Rejects the wrong shape early. |
| Ask about a pattern | `matches!(value, pattern)` | Produces `bool`. |
| Refine an arm | `pattern if condition => ...` | Checks the guard before selecting the arm. |

Use the [Option](https://doc.rust-lang.org/std/option/enum.Option.html) and
[Result](https://doc.rust-lang.org/std/result/enum.Result.html) references
to check exact signatures. Next, [collections and bytes](/pages/1/14/)
connect these outcome shapes to bounded buffers and repeated work.
