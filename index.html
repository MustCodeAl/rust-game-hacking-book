How the book fits together

Section titled “How the book fits together”

A game shows you a result: a number changes, a character moves, or a frame is drawn. To understand that result, you can look closer at the rule that changed the game’s state, the bytes that held it, and the instructions that acted on those bytes. You can also look outward at the files, messages, and operating system boundaries around the process. Those are connected views of the same running game, and each chapter gives you another way to explain what you see.

The opening chapters establish the computer, game, programming, Rust, and memory concepts. The middle of the book follows state through debuggers, object layouts, executable analysis, hooks, graphics, networks, and game files. The later chapters connect scripting and virtual machines to Windows processes, driver boundaries, integrity checks, hardware, and emulators. Worked labs stay beside the ideas they demonstrate, so you can read an explanation and then test its consequences.

Read from the beginning for the guided path. For a particular question, use the complete contents or site search to return to the relevant concept, diagram, code example, or lab. Each lesson explains its own example; you only need the ideas introduced in earlier lessons, not the names or values from an earlier exercise.

How the code is taught

Make every assumption visible.

The compiler is a coach. It catches dangling references, mixed-up types, and many memory mistakes before the program runs.

Danger stays visible. When an operating-system call needs raw pointers, that small unsafe boundary states exactly why the operation is valid.

Feedback stays close. Builds, tests, formatting, and documentation use a small set of repeatable commands.

What you need

Section titled “What you need”
  • A Windows virtual machine for the Windows-specific labs
  • Rust and Cargo
  • A debugger such as x64dbg and a memory scanner such as Cheat Engine
  • Curiosity, patience, and a version-pinned target

The original PDF is still available as a legacy snapshot. It predates this rewrite, so the website is the source of truth.

The portable algorithms used throughout the book are collected in the repository’s rust-labs crate. Run cargo test there to experiment with byte parsing, pattern scanning, angle math, and world-to-screen projection without attaching to any process. The advanced lessons in Chapters 3, 9, and 12 use advanced-memory-labs for toy obfuscation, authenticated encryption, and read-only x86-64 translation of offline capture files.

Interactive learning tools

Section titled “Interactive learning tools”

Ownership lessons include step-by-step memory models inspired by Aquascope, which presents both Rust’s execution behavior and the facts checked by the borrow checker. Knowledge checks are inspired by mdbook-quiz, including multiple-choice, short-answer, and compile-tracing questions with saved attempts. Memory figures and diagrams are drawn by the site itself, so every one follows your chosen palette.
